# GPUTrain 系统设计评审（2026-10-10）

评审范围：`dev` 分支实现基线 `9cd8ff0c`、现有 SSH 设计、README、运维文档及本次会话的单机训练/监控现象。未读取目标 GPU 主机上的当前运行状态，以下“待验证”不能解释为确定缺陷。本轮仅更新文档，不修改代码。

## 结论

方向可行：控制面统一管理多台服务器，SSH 配合用户级 `systemd` 保留训练进程，数据库记录任务与 GPU 租约，断线后对账。当前设计要进入稳定使用，还需把**终态证据与租约释放、数据库迁移门禁、可观测性错误表达、真实多机验收**定义成明确的交付标准。

## 缺口与建议

| 优先级 | 发现及证据 | 功能/设计影响 | 建议验收条件 |
| --- | --- | --- | --- |
| P0 | 1-step 任务的远端日志曾出现完成和 checkpoint，页面长期“状态待核对”。代码 `SshJobDispatcher.status` 对 `LoadState` 非 loaded 返回 `UNKNOWN`，`SshJobReconciler` 在 UNKNOWN 且再次 UNKNOWN 时保持原态；若临时单元被回收或状态不可读，缺少独立持久的退出结果来源。该机制是**可能原因**，还需目标机证据确认。 | 用户无法确认成功，三卡租约可能长期占用。 | 任务成功、失败、停止各有持久退出码/完成证据；单元消失、控制面重启、SSH 断开恢复都能确定终态或给出明确人工处理路径；终态后核对租约。 |
| P0 | 曾因 `train_job_alert` 缺表，点击监控触发 SQL 错误；表定义存在于 `gputrain_phase4.sql`，既有 MySQL 数据目录不会重跑初始化 SQL。 | 功能在后端启动后才暴露缺表；页面报错。 | 发布前按 schema 版本检查所需表/列/索引；迁移可重复、可回滚，缺失时阻止启动或明确标记降级；监控接口烟测通过。 |
| P1 | 旧 README 以单机 Runner 为当前主线，SSH 设计提出删除 Runner，仓库仍保留 Runner 接口与模块。 | 操作人员可能按旧路径部署或误认为迁移完成。 | 首页指向当前设计；历史方案标注状态；确定旧 Runner 新提交的禁用/退场标准及数据保留期。 |
| P1 | SSH 设计提出“错误不伪装为暂无数据”，监控页曾出现异常与空数据混用。 | 监控失败易被误读成无告警。 | 日志/指标/告警/资源分别显示加载、空、错误、过期和最后更新时间；接口失败不返回或渲染成成功空集合。 |
| P1 | 设计接受标准要求两台服务器、密码/私钥、两个账户同卡视角、停止和断线恢复；现有会话只证明单台主机一条短任务的部分链路。 | 多机隔离、凭据路径和租约唯一性仍无实机证据。 | 执行原设计四条验收项，保存脱敏的任务 ID、设备、单元状态、退出码、日志 offset、租约前后记录。 |
| P1 | `Linger=yes` 与页面状态的关系不直观；状态页只看用户管理器能力还不足以保证训练环境可用。 | 用户可能把“在线”理解为可提交。 | 连接测试分项报告 SSH、指纹、认证、GPU、用户 systemd、允许根目录及固定 profile，给出最近成功时间。 |
| P2 | 数据库 root、`gputrain` 用户与后端配置密码轮换曾需人工排查；现有部署说明以 Runner 为主。 | 重启/迁移时易出现密码漂移和缺表。 | 运维文档包含已有数据目录、用户密码轮换、备份恢复及迁移前后核对；不记录明文秘密。 |
| P2 | 任务 profile 固定为三卡、1–5 步的 `docowl2-srfund`；没有通用训练任务模型。 | 页面“训练平台”名称可能使用户期待自定义训练。 | 产品说明清楚标明受支持 profile；将通用任务、跨机训练、自动环境安装作为后续独立设计。 |

## 建议先后顺序

1. 在目标机核对已有“待核对”任务的 `systemctl --user show` 结果、进程、退出码、日志尾部及三条租约，先定性 P0 原因；不能只用日志中的 `training complete` 判成功。
2. 补齐持久终态证据和迁移门禁的设计及测试场景，再安排代码实现；本轮不实施。
3. 完成监控错误态、连接能力分项及文档同步。
4. 用两台真实服务器完成端到端验收后，才决定旧 Runner 代码/工作树清理和迁移完成标记。

## 待决策问题

- 远端终态证据采用保留 `systemd` 单元、退出状态文件，还是两者结合？证据文件损坏或主机重装时由谁确认租约释放？
- 管理员是否允许代管/代测其他用户的 Linux 账户？凭据删除、主机指纹变更和账户撤销时，运行中的任务如何处置？
- 日志、指标、告警、GPU 快照保留多久；是否需要数据库体量上限和归档策略？
- 旧 Runner 的“只读兼容”何时结束，数据库历史表何时允许物理清理？
