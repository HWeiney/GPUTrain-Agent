# GPUTrain 前端实测闭环设计

## 目标与范围

让开发者在本机运行 Vite 前端，连接部署在 GPU 服务器上的控制面，完成 Runner/设备状态确认、固定 DocOwl2-SRFUND 任务提交、运行监控以及停止或取消。正式使用时将前端静态文件与控制面部署在服务器。此轮不加入浏览器 SSH、任意训练命令、GPU 预约、Agent 页面或通用服务器资产管理。

## 当前证据

- 前端只有训练总览、GPU 设备、训练任务三页；任务页缺少明确的 GPU 选择、权限控制、停止确认与状态感知。
- `TrainOverviewService` 固定返回 `READY, 0, 0`，总览不能代表实际状态。
- `JobService.stop` 要求任务已有 `startCommandId`，但前端对未终结任务一律提供“停止”，导致排队任务操作失败。
- `PENDING/QUEUED → CANCELED` 已在状态机中，尚无面向用户的取消接口。
- 前端测试与生产构建通过；`vue-tsc --noEmit` 失败，其中 GPUTrain API 测试使用过时提交载荷，任务页有隐式 `any`；本机 5173/8080 当时无服务，尚无浏览器端到端验收。

## 运行拓扑

开发模式：浏览器 → 本机 Vite → 可配置的服务器控制面 HTTPS 地址；服务器上的 Runner 依现有协议主动连接同一控制面。Vite 代理目标通过本地环境变量配置，凭据只进入若依登录态，不写入仓库或前端配置。生产模式：浏览器 → 服务器反向代理 → 前端静态文件和控制面；Runner 继续使用服务器上的控制面 HTTPS origin。页面不直接进行 SSH 连接，也不接收 Runner 密钥。

Vite 启动时固定一个代理目标。切换服务器需要重启开发服务器并重新登录；页面内不提供运行时任意 URL 输入，避免出现多个控制面数据混用和令牌发送到错误地址。

## 页面与数据流

1. **环境状态**：工作台展示控制面响应、在线 Runner 数与当前任务数。后端使用已有任务记录、Runner 心跳/在线 TTL 计算实时值；如果依赖不可用，返回明确的降级/错误状态，不显示固定 `READY`。设备页展示采样时间、身份、租约和外部占用；这些是观测值，不等于调度承诺。
2. **提交**：任务表单保留唯一固定 profile 和 1–5 步限制。用户从最新设备列表显式选择恰好 3 个 GPU UUID，页面展示显存余量、快照时间、MIG 与外部占用；对明显不符合后端约束的选择禁用提交。后端仍做最终原子调度验证。提交时生成一次性 `requestKey`；失败后允许用同一 key 安全重试，重新打开表单才产生新 key。只有 `train:job:manage` 用户看得到操作。
3. **任务列表**：显示中文状态、最近更新时间、Runner、GPU 数，自动刷新并提供手动刷新。任务刚提交时显示排队/分配状态，避免用户把“未运行”当成故障。列表后端分页或有界查询，避免长期使用后无限增长。
4. **取消/停止**：`PENDING/QUEUED` 提供“取消”，后端以状态条件更新为 `CANCELED`；与调度竞争时返回当前状态，由前端刷新后重选操作。已有启动命令且可停止的状态提供“停止”，操作前确认任务 ID 与影响；`STOPPING` 和终结态禁用重复操作。隔离态继续按现有后端安全规则处理，不假设进程已退出。
5. **监控**：详情保持任务状态、日志、指标、告警和 GPU 资源历史。日志初始读取及 SSE 增量使用事件游标去重；请求失败在详情内可见并可重试，不将失败显示成“暂无数据”。切换任务或关闭详情时取消旧请求与定时器，防止旧任务结果覆盖新任务。对时间、缺失值和空状态给出可读显示。

## 错误与权限

前端展示后端明确的权限、资源不足、Runner 离线和状态冲突信息；不会将所有提交失败都压成一个通用错误。后端继续根据登录用户校验任务归属，GPU/Runner 列表只返回当前权限允许的数据。浏览器不存储或显示 Runner 凭据、服务器密码、SSH 密钥。所有危险操作由后端校验，前端权限只负责避免误导性按钮。

## 验收

- 本机前端代理远程 HTTPS 控制面，登录后能读取工作台、设备和任务；服务器 Runner 心跳能在页面上反映在线状态。
- 选择 3 张符合条件的 GPU，提交 1-step 任务，观察 `QUEUED/STARTING/RUNNING/终结态` 与日志、指标、告警、资源数据；任务运行期间可确认停止，停后核对最终状态与租约。
- 排队任务可取消；调度竞争、权限不足、Runner 离线、快照过期、后端断连都给出正确反馈且不产生重复任务。
- GPUTrain 相关前端类型检查、单元/组件测试、生产构建通过；后端任务状态与权限测试通过。另记录一次真实浏览器联调的环境、时间和结果。

## 分阶段边界

先完成开发代理与真实状态、提交与取消/停止、监控可靠性，再做服务器实测。Runner 管理、Agent 工作台、预约和多 profile 实验管理各自作为后续独立设计，不在此轮混入。
